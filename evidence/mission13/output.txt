## 4. Hash != authenticity: attacker modifies the file AND regenerates the hash

$ echo 'Approved configuration' > config.txt && sha256sum config.txt > config.sha256

$ echo 'malicious_setting=on' >> config.txt

$ sha256sum config.txt > config.sha256   # attacker can write the .sha256 too

$ sha256sum -c config.sha256
config.txt: OK
=> Check PASSES even though the file was tampered with: the hash only proves
   'unchanged since the hash was made', not WHO made it.

## 5. Keyed hash (HMAC): without the secret key the attacker cannot forge the tag
